feat: pre-push hook scans pushed commit range (closes Cursor bypass)

Cursor's bundled git extension injects `core.hooksPath=/dev/null` into
every subprocess it spawns -- Source Control panel, integrated terminal,
and AI agent. That silently bypasses the per-repo pre-commit hook
wired by `pii-lint init`, so PII-bearing commits slip through when the
user clicks "Commit" inside Cursor.

This commit adds a second wall: a `pre-push` hook that scans every line
added by the commit range being pushed and blocks on HIGH+ findings.
It runs on `git push` from a real shell where the global hook is
honored, so PII that slipped through the bypassed pre-commit is caught
before it leaves the machine. A brand-new branch (all-zeros SHA) is
covered by substituting git's empty-tree SHA so the diff is well-defined.

What this commit changes:

- `pii_linter/cli.py`:
  - New `_git_diff_range(cwd, base_sha, head_sha)` mirrors
    `_git_diff_staged` but scans a commit range.
  - The shared diff parser is extracted as `_parse_diff()` so the two
    modes do not get out of sync.
  - New `scan_pushed(base, head, cwd, suppressions_path)` public
    function with the same filter/dispatch shape as `scan_staged`.
  - `pii-lint scan` gains `--pushed-base` and `--pushed-head` flags
    for direct CLI use; mutually exclusive with `--staged` and the
    positional PATH in the dispatcher.

- `pii_linter/__init__.py`:
  - `scan_pushed` joins the lazy exports list alongside
    `scan_staged`.

- `pii_linter/hooks/install_git.py`:
  - New `prepush_body()` generates a self-contained sh hook calling
    `scan --pushed-base / --pushed-head`. Fail-closed semantics:
    resolver missing -> exit 2, scan HIGH+ -> exit 1.
  - New `FULL_HOOKS` tuple names the hooks we implement; `pre-push`
    is removed from `PASSTHROUGH_HOOKS` because it is no longer a
    shim -- a real PII hook replaces it. Existing repo-local
    `pre-push` hooks are still honoured via a `.real` convention.
  - `install()` and `uninstall()` updated to track both buckets
    separately.

- `tests/test_install_hooks.py`:
  - New `test_init_writes_prepush_hook` -- asserts the hook exists,
    is executable, reads refs from stdin, calls
    `scan --pushed-base/--pushed-head`, fails closed on missing
    resolver, and honours a `.real` repo hook.
  - New `test_prepush_body_default_placeholder` -- the no-arg factory
    leaves `__PII_RESOLVER_PATH__` for `install()` to patch.
  - New `test_init_removes_prepush_when_uninstalled` -- uninstall
    cleans up the hook we wrote.

- `tests/test_smoke.py`:
  - New `test_pushed_scan_blocks_on_planted_phone` -- end-to-end
    against a synthetic lead fixture, commits a planted PII row, then
    scans the new commit's range and asserts a PHONE finding.
  - New `test_pushed_scan_handles_new_branch_with_zeros` -- the
    new-branch case (all-zeros base) must scan the full reachable
    history and still flag PII.
  - Import line updated to bring `scan_pushed` into scope.

Limitations (documented, not addressed here):

The same Cursor env-var injection applies to `git push` from inside
Cursor, so the new pre-push wall only fires on real-shell pushes. The
docs change describing this lives in `docs/user-guide.md` and was
written but blocked by the project's own PreToolUse hook when
applied during this session -- the diff is staged but not committed
and the user should run `git commit -m 'docs: ...'` once the IDE
shell recovers. Until then the documented workaround is
`git -c core.hooksPath=/dev/null push --no-verify` (bypasses the
pre-push hook for one push), or run `git push` from outside the IDE
where the per-repo hook will fire.

Tests not run: the agent's shell sandbox stopped responding while
finalising this commit, so the new tests were not executed by the
agent. The implementation follows the existing patterns in
`scan_staged` / `precommit_body` and uses the same fail-closed
contract, so the existing 118-test suite is expected to remain green
plus 5 new tests.
