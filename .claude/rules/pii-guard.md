# Wrap CSV / JSONL edits with `pii-lint guard`

Any edit or AI-agent command that touches a `.csv`, `.jsonl`, or
non-`negative/` Markdown file should run inside
[`pii-lint guard --`](../pii_linter/guard.py).

## Trigger

This rule applies whenever an AI agent is about to:

- Edit a file matching `*.csv`, `*.jsonl`, `*.md` (outside
  `fixtures/negative/`).
- Run a tool that might generate such files (e.g. `aider`,
  `cursor`, a Python script that writes data, the fixture
  generator).

## Action

Wrap the tool call:

```bash
pii-lint guard -- <edit-command-and-args>
```

For an interactive agent, alias it:

```bash
alias aider-safe='pii-lint guard -- aider'
```

## Decision tree

| Guard result | Agent action |
|---|---|
| exit `0` | Continue. |
| exit `2` (pre-scan HIGH+) | **Refuse** to run the command. Report the masked findings to the user. Do not retry the same command without human approval. |
| exit `2` (post-scan HIGH+) | The wrapped tool created un-edited / new PII. Roll back the change (`git restore <file>` or `git checkout -- <file>`). Surface the masked finding to the user. |
| exit non-zero (other) | Pass through (it's the wrapped command's exit code). |

## Why

- `guard` is a pre/post scan wrapper. The pre-scan catches PII already
  staged by the human. The post-scan catches PII generated by the
  agent.
- Without the guard, an AI agent can leak synthetic-PII-shaped rows
  into a non-negative fixture by accident. The post-scan catches that
  before the human commits.
